# Sources for game-localization

Every page below was opened on 2026-11-14. Claims in the skill with no source here are this skill's own rules.

## Strings and message formats

- IGDA Localization SIG, "Best Practices for Game Localization" v22 (IGDA, republished 2021) - https://igda-website.s3.us-east-2.amazonaws.com/wp-content/uploads/2021/04/09142137/Best-Practices-for-Game-Localization-v22.pdf - supports: isolate all text into a resource file per language; hard-coded text sends translators into source code; variable order changes by language; 30 to 40 percent rule of thumb; automatic wrap with override; scroll or pop-up instead of cut-off words; space before ! ? ; : and double quotes in French, U+00A0 or a token; runtime subtitles, not burned in; UTF-8; track text in textures and models, or use icons and symbols; font approval before translation; familiarization time (3 days small title, a month for large MMORPGs); naming time (a week to 6 weeks); glossary, style guide and pronunciation; record naming reasons; proofread source; commit to a date to lock source changes; list of source text changes per build; traffic light (green stable, orange minor changes, red translate at own risk); each MMO content patch as its own cycle; linguist on call; LQA separation of suggestions, regression on more than one build, waiver justification, lead translator decides; four culturalization areas, context proximity, Kakuto Chojin, be surgical - checked 2026-11-14
- Mozilla L10n, "Best practices for developers" - https://mozilla-l10n.github.io/documentation/localization/dev_best_practices.html - supports: update the string ID when meaning changes, not for English-only typo fixes; bookmark noun/verb ambiguity; explain variables in comments; avoid concatenation, use placeholders; do not reuse strings in different contexts; design for at least +30 percent - checked 2026-11-14
- Godot Engine, "Internationalizing games" - https://docs.godotengine.org/en/stable/tutorials/i18n/internationalizing_games.html - supports: plain-English source strings (rather than message codes LIKE_THIS) can be ambiguous, and translation contexts resolve it; fallback to the project fallback locale or en; default font covers a subset of Latin-1, Noto fonts - checked 2026-11-14
- ICU, "Formatting Messages" - https://unicode-org.github.io/icu/userguide/format_parse/messages/ - supports: concatenated fragments cannot be rearranged by translators; full sentences in sub-messages; select outside, plural nested - checked 2026-11-14
- W3C Internationalization, "Composite messages" - https://www.w3.org/International/articles/composite-messages/ - supports: use a topic-comment approach whenever possible - checked 2026-11-14
- Project Fluent, "Good Practices for Developers" (GitHub wiki) - https://github.com/projectfluent/fluent/wiki/Good-Practices-for-Developers - supports: prefer WET over DRY; prefer separate messages over variants for UI logic - checked 2026-11-14
- Project Fluent, "Comments" - https://projectfluent.org/fluent/guide/comments.html - supports: a comment right above a message is part of it and tools present them together - checked 2026-11-14
- Project Fluent, "Selectors" - https://projectfluent.org/fluent/guide/selectors.html - supports: `*` marks the default variant; a default variant is required - checked 2026-11-14
- Project Fluent, "Terms" - https://projectfluent.org/fluent/guide/terms.html - supports: terms are referenced from other messages, suit brand names and glossary items, and can carry variants such as grammatical case - checked 2026-11-14
- Unicode, "UTS #35 Part 9: MessageFormat" (CLDR 49, dated 2026-10-21) - https://www.unicode.org/reports/tr35/tr35-messageFormat.html - supports: stability policy; functions marked Draft are not stable - checked 2026-11-14
- Unicode, "MessageFormat 2" - https://messageformat.unicode.org/ - supports: built into ICU4C and ICU4J and "soon" ECMA-402 - checked 2026-11-14
- TC39, "proposal-intl-messageformat" (GitHub) - https://github.com/tc39/proposal-intl-messageformat - supports: Intl.MessageFormat is at Stage 1 - checked 2026-11-14

## Plurals and Intl

- Unicode CLDR, "Language Plural Rules" - https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html - supports: English one/other; Arabic zero/one/two/few/many/other; Russian and Polish one/few/many/other; Japanese other only; Portuguese (pt) and French put 0 and 1 in one; European Portuguese (pt_PT) one is i = 1 and v = 0 - checked 2026-11-14
- MDN, "Intl.PluralRules" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/PluralRules - supports: select returns the plural category; ordinal type; baseline since September 2019 - checked 2026-11-14
- MDN, "Intl.NumberFormat() constructor" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/NumberFormat/NumberFormat - supports: currency has no default and must be given with style currency; compact notation example 988M - checked 2026-11-14
- MDN, "Intl.DateTimeFormat" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/DateTimeFormat - supports: timeZone option; formatRange formats a range concisely - checked 2026-11-14
- MDN, "Intl.RelativeTimeFormat" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/RelativeTimeFormat - supports: numeric auto gives words; format takes the unit; baseline since September 2020 - checked 2026-11-14
- MDN, "Intl.ListFormat" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/ListFormat - supports: conjunction, disjunction, unit; German "oder"; baseline since April 2021 - checked 2026-11-14
- MDN, "Intl.Segmenter" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter - supports: Japanese, Chinese, Thai, Lao, Khmer, Myanmar use no spaces between words; baseline since April 2024 - checked 2026-11-14
- MDN, "Intl" - https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl - supports: Collator for language-sensitive comparison; DisplayNames for language names; default locale when none is given - checked 2026-11-14
- Bun, "Web APIs" - https://bun.com/docs/runtime/web-apis - supports: the page does not list Intl, so Bun's Intl coverage is checked by running code, not by docs - checked 2026-11-14

## Layout, scripts and fonts

- W3C Internationalization, "Text size in translation" - https://www.w3.org/International/articles/article-text-size - supports: the expansion table from IBM; allow text to reflow and avoid small fixed-width containers - checked 2026-11-14
- MDN, "CanvasRenderingContext2D: fillText()" - https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/fillText - supports: maxWidth adjusts kerning, condenses or scales the font down - checked 2026-11-14
- MDN, "CanvasRenderingContext2D: direction" - https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/direction - supports: ltr, rtl, inherit (default) - checked 2026-11-14
- MDN, "CanvasRenderingContext2D: textAlign" - https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/textAlign - supports: start and end follow direction; left and right do not - checked 2026-11-14
- MDN, "FontFaceSet: load()" - https://developer.mozilla.org/en-US/docs/Web/API/FontFaceSet/load - supports: the promise fulfils when the fonts are loaded and rejects if one fails - checked 2026-11-14
- W3C Internationalization, "Structural markup and right-to-left text in HTML" - https://www.w3.org/International/questions/qa-html-dir - supports: dir="rtl" on the html tag; never use CSS to apply the base direction; use logical start and end - checked 2026-11-14
- MDN, "CSS logical properties and values" - https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Logical_properties_and_values - supports: logical properties follow writing direction, including vertical CJK writing - checked 2026-11-14
- W3C Internationalization, "Inline markup and bidirectional text in HTML" - https://www.w3.org/International/articles/inline-bidi-markup/ - supports: dir=auto or bdi around inserted text; direction from the first strong character - checked 2026-11-14
- W3C Internationalization, "Why use the language attribute?" - https://www.w3.org/International/questions/qa-lang-why - supports: shared Han code points but readers expect different glyphs; hyphenation depends on language - checked 2026-11-14
- W3C Internationalization, "Approaches to line breaking" - https://www.w3.org/International/articles/typography/linebreak - supports: Khmer and Thai line breaks by dictionary lookup; lines should not start with phrase-ending punctuation - checked 2026-11-14
- MDN, "line-break" - https://developer.mozilla.org/en-US/docs/Web/CSS/line-break - supports: sets how CJK lines break around punctuation and symbols - checked 2026-11-14
- MDN, "unicode-range" - https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/unicode-range - supports: the font downloads only when the page uses a character in the range - checked 2026-11-14
- W3C Internationalization, "Personal names around the world" - https://www.w3.org/International/questions/qa-personal-names - supports: use the full name as given where possible; allow long names, hyphens, apostrophes, spaces; ask how to address the person - checked 2026-11-14
- Natalia Shuhman (Alconost), article republished on igda.org - https://igda.org/?p=6955 - supports: genderless English characters need gender information for translators; give each character's background - checked 2026-11-14
- Ocean Drive Studio, "Localizing the World of Lost Eidolons" (2023) - https://oceandrive.studio/2023/12/01/localizing-the-world-of-lost-eidolons/ - supports: Ethan renamed Eden; avoided 1:1 copies of real cultures and stereotypes; development had run over a year before localization started - checked 2026-11-14
