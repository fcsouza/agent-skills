# Sources

Each line: source, URL, what it supports, date checked.

- Elysia docs, "Extend Context" - https://elysiajs.com/patterns/extends-context - supports: "store is a representation of a single-source-of-truth global mutable object for the entire Elysia app"; "derive is assigned once a new request starts"; derive is called at transform, before validation - checked 2026-11-14
- Elysia docs, "Lifecycle" - https://elysiajs.com/essential/life-cycle - supports: "properties assigned by derive are unique and not shared with other requests"; "Event will only apply to routes after it is registered"; After Response is recommended for logging and analytics - checked 2026-11-14
- Elysia docs, "Plugin" - https://elysiajs.com/essential/plugin - supports: `new Elysia({ name })` deduplicates a plugin; `{ as: 'global' }` applies a hook to all instances that use the plugin; logging is listed as a global dependency - checked 2026-11-14
- Elysia 1.4.32 published types, `dist/index.d.ts` - https://unpkg.com/elysia@1.4.32/dist/index.d.ts - supports: the `derive({ as }, fn)` overload, documented as "Derive new property for each request" - checked 2026-11-14
- Elysia 1.4.32 published types, `dist/types.d.ts` - https://unpkg.com/elysia@1.4.32/dist/types.d.ts - supports: the `ErrorHandler` context marks derived keys `NeverKey` for `code: 'NOT_FOUND'` and `code: 'PARSE'`, and `Partial` for `UNKNOWN` and most other codes - checked 2026-11-14
- Rob Ewaschuk, "Monitoring Distributed Systems" (Site Reliability Engineering, chapter 6, O'Reilly Media; web edition sre.google) - https://sre.google/sre-book/monitoring-distributed-systems/ - supports: a mean hides the slow tail, so collect request counts bucketed by latency (histogram); "Every page should be actionable"; alerts go to tickets, email or pages - checked 2026-11-14
- Glenn Fiedler, "Fix Your Timestep!" (Gaffer On Games, June 10, 2004) - https://gafferongames.com/post/fix_your_timestep/ - supports: a simulation that takes longer in real time than the time it simulates falls behind ("spiral of death"); "I recommend leaving some headroom" - checked 2026-11-14
- OpenTelemetry docs, "Metrics" - https://opentelemetry.io/docs/concepts/signals/metrics/ - supports: Counter only goes up; UpDownCounter can go down (queue length); Histogram is a client-side aggregation of values such as request latencies - checked 2026-11-14
- OpenTelemetry semantic conventions, "Metrics semantic conventions" - https://opentelemetry.io/docs/specs/semconv/general/metrics/ - supports: durations SHOULD use seconds (`s`); integer counts use curly-brace annotations such as `{error}`, singular - checked 2026-11-14
- Prometheus docs, "Metric and label naming" - https://prometheus.io/docs/practices/naming/ - supports: every label combination is a new time series; "Do not use labels to store dimensions with high cardinality ... such as user IDs" - checked 2026-11-14
- IETF RFC 6455, "The WebSocket Protocol", section 7.4.1 (2011) - https://www.rfc-editor.org/rfc/rfc6455.html#section-7.4.1 - supports: 1000 normal closure; 1001 "going away", such as a server going down or a browser navigating away; 1006 connection closed abnormally, without a Close control frame - checked 2026-11-14
- Bun docs, "WebSockets" - https://bun.com/docs/runtime/http/websockets - supports: the server `close(ws, code, message)` handler receives the close code; a local run on Bun 1.4.4 logged code 1000 for a client `close(1000)` and 1006 for a client process killed with SIGKILL - checked 2026-11-14
