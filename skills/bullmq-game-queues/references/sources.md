# Sources

Checked against `bullmq` 6.7.6 and `ioredis` 6.0.0, the versions pinned in the repo's root `package.json`, and against the published types in `node_modules/bullmq`.

- BullMQ, "What is BullMQ" (BullMQ docs) - https://docs.bullmq.io - supports: vendor pointer for queue, worker and event APIs that this skill does not restate - checked 2026-11-14
- BullMQ, "Migrate from v5 to v6" (BullMQ docs) - https://docs.bullmq.io/guide/migrations/migrate-from-v5-to-v6 - supports: "The legacy repeat option `repeat.utc` is removed. To run cron schedules in UTC, use: `upsertJobScheduler(..., { tz: 'UTC' })`"; legacy repeatable APIs (`Queue.add(..., { repeat })`, `getRepeatableJobs`, `removeRepeatable*`) are removed - checked 2026-11-14
- BullMQ, "Connections" (BullMQ docs) - https://docs.bullmq.io/guide/connections - supports: "By default, BullMQ creates Redis connections with ioredis"; workers need `maxRetriesPerRequest` null; a producer behind an HTTP endpoint should leave it at the default "or set it to another value, maybe 1 so that the user gets an error quickly"; do not use the ioredis `keyPrefix` option - checked 2026-11-14
- BullMQ, "Job Schedulers" (BullMQ docs) - https://docs.bullmq.io/guide/job-schedulers - supports: `upsertJobScheduler` creates or updates without duplicates; "all jobs produced by the Job Scheduler inherit these settings"; "The scheduler will only generate new jobs when the last job begins processing"; use `tz: 'UTC'` for UTC cron - checked 2026-11-14
- BullMQ, "Prioritized" (BullMQ docs) - https://docs.bullmq.io/guide/jobs/prioritized - supports: priorities run from 1 to 2 097 151, a lower number is a higher priority, and "Jobs without a `priority` assigned will get the highest priority, being processed before jobs with priorities assigned to them" - checked 2026-11-14
- BullMQ, "Job Ids" (BullMQ docs) - https://docs.bullmq.io/guide/jobs/job-ids - supports: a job added with an existing id "will just be ignored"; removed jobs do not count as duplicates; custom ids must not contain colons or be integers - checked 2026-11-14
- BullMQ, "Idempotent jobs" (BullMQ docs) - https://docs.bullmq.io/patterns/idempotent-jobs - supports: "it should not make a difference to the final state of the system if a job successfully completes on its first attempt, or if it fails initially and succeeds when retried"; keep jobs atomic and simple - checked 2026-11-14
- BullMQ, "Retrying failing jobs" (BullMQ docs) - https://docs.bullmq.io/guide/retrying-failing-jobs - supports: exponential backoff waits `2 ^ (attempts - 1) * delay` ms; a failed job moves to the failed set and stays there or is removed per queue settings - checked 2026-11-14
- BullMQ, "Rate limiting" (BullMQ docs) - https://docs.bullmq.io/guide/rate-limiting - supports: "The rate limiter is global"; group keys (per-customer limits) were removed in BullMQ 3.0 - checked 2026-11-14
- BullMQ, "Delayed" (BullMQ docs) - https://docs.bullmq.io/guide/jobs/delayed - supports: a delayed job is not guaranteed to run at the exact delayed time; it depends on how busy the workers are - checked 2026-11-14
- BullMQ, "Stalled Jobs" (BullMQ docs) - https://docs.bullmq.io/guide/workers/stalled-jobs - supports: a CPU-heavy processor may fail to renew its lock; a stalled job is processed again or, past its stall limit, moved to the failed set - checked 2026-11-14
- BullMQ, "Events" (BullMQ docs) - https://docs.bullmq.io/guide/events - supports: "The `QueueEvents` class is implemented using Redis streams", so events are not lost during disconnections; worker listeners see only their own process - checked 2026-11-14
- Redis, "Redis Streams" (Redis docs) - https://redis.io/docs/latest/develop/data-types/streams/ - supports: "A Redis stream is a data structure that acts like an append-only log", the structure behind `QueueEvents` - checked 2026-11-14
- BullMQ 6.7.6 published types, `repeat-options.d.ts` - https://unpkg.com/bullmq@6.7.6/dist/esm/interfaces/repeat-options.d.ts - supports: `RepeatOptions` has `tz` and no `utc` - checked 2026-11-14
- BullMQ 6.7.6 published types, `redis-options.d.ts` - https://unpkg.com/bullmq@6.7.6/dist/esm/interfaces/redis-options.d.ts - supports: BullMQ exports its own `RedisOptions` and `ConnectionOptions`, so the config needs no ioredis type import - checked 2026-11-14
- BullMQ 6.7.6 published types, `queue-options.d.ts` - https://unpkg.com/bullmq@6.7.6/dist/esm/interfaces/queue-options.d.ts - supports: `prefix` is "Prefix for all queue keys (Redis backend only). Defaults to `bull`.", and `QueueEventsOptions` accepts `prefix` - checked 2026-11-14
- BullMQ 6.7.6 `classes/job-scheduler.js` - https://unpkg.com/bullmq@6.7.6/dist/esm/classes/job-scheduler.js - supports: a scheduler-produced job gets id `repeat:${jobSchedulerId}:${nextMillis}` and `repeatJobKey: jobSchedulerId`, so the id is unique per run - checked 2026-11-14
- BullMQ 6.7.6 `package.json` - https://unpkg.com/bullmq@6.7.6/package.json - supports: `ioredis` is listed in `peerDependencies` (`>=5.0.0`) and marked `optional` in `peerDependenciesMeta` - checked 2026-11-14
