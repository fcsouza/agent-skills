# Sources

Each entry was opened on the date shown.

- Gabriel Gambetta, "Fast-Paced Multiplayer (Part I): Client-Server Game Architecture" (gabrielgambetta.com) - https://www.gabrielgambetta.com/client-server-game-architecture.html - supports: authoritative server, never trust the client; dumb clients work for slow turn-based games but feel laggy for fast-paced ones - checked 2026-11-14
- Gabriel Gambetta, "Fast-Paced Multiplayer (Part II): Client-Side Prediction and Server Reconciliation" (gabrielgambetta.com) - https://www.gabrielgambetta.com/client-side-prediction-server-reconciliation.html - supports: sequence numbers on inputs, server echoes the last processed one, client replays unacknowledged inputs; hold irreversible outcomes such as death until the server confirms - checked 2026-11-14
- Gabriel Gambetta, "Fast-Paced Multiplayer (Part III): Entity Interpolation" (gabrielgambetta.com) - https://www.gabrielgambetta.com/entity-interpolation.html - supports: dead reckoning for predictable motion such as cars, entity interpolation in the past for players who change direction instantly - checked 2026-11-14
- Gabriel Gambetta, "Fast-Paced Multiplayer (Part IV): Lag Compensation" (gabrielgambetta.com) - https://www.gabrielgambetta.com/lag-compensation.html - supports: server reconstructs the world at the shot's timestamp; a target can be hit just after taking cover - checked 2026-11-14
- Valve Developer Community, "Source Multiplayer Networking" (wiki) - https://developer.valvesoftware.com/wiki/Source_Multiplayer_Networking - supports: delta snapshots against the last acknowledged update, full snapshots on join or heavy loss; 100 ms default interpolation period so one lost snapshot still leaves two; extrapolation capped at 0.25 s; prediction errors smoothed over time; lag compensation - checked 2026-11-14 (WebFetch gets HTTP 403; re-opened with the Firecrawl CLI, which shows: "Source defaults to an interpolation period ('lerp') of 100-milliseconds (`cl_interp 0.1`)" and "The extrapolation is done only for 0.25 seconds of packet loss (`cl_extrapolate_amount`)")
- Glenn Fiedler, "Deterministic Lockstep" (Gaffer On Games, 2014) - https://gafferongames.com/post/deterministic_lockstep/ - supports: send only inputs, bandwidth independent of object count; floating point differs across compilers, operating systems and instruction sets - checked 2026-11-14
- Glenn Fiedler, "Snapshot Interpolation" (Gaffer On Games, 2014) - https://gafferongames.com/post/snapshot_interpolation/ - supports: interpolation buffer; lost snapshots can be skipped; lockstep recommended for 2-4 players at most because everyone waits for the most lagged player - checked 2026-11-14
- Glenn Fiedler, "Snapshot Compression" (Gaffer On Games, 2015) - https://gafferongames.com/post/snapshot_compression/ - supports: encode deltas only against baselines the receiver has acknowledged; quantize floats to cut bandwidth - checked 2026-11-14
- Glenn Fiedler, "State Synchronization" (Gaffer On Games, 2015) - https://gafferongames.com/post/state_synchronization/ - supports: snap physics state hard and smooth only the visual error, fast for large pops; priority accumulator: add each object's priority to its accumulator every frame, sort, fill the packet to the budget, reset the accumulator for objects that fit and leave it for those that did not; the player's own object gets a priority high enough to be in every packet - checked 2026-11-14
- Glenn Fiedler, "Networked Physics in Virtual Reality" (Gaffer On Games, 2018) - https://gafferongames.com/post/networked_physics_in_virtual_reality/ - supports: distributed simulation with an authority scheme for a non-competitive physics game, less secure than client/server - checked 2026-11-14
- Glenn Fiedler, "Fix Your Timestep!" (Gaffer On Games, 2004) - https://gafferongames.com/post/fix_your_timestep/ - supports: fixed delta time with an accumulator, interpolate with the leftover alpha, spiral of death - checked 2026-11-14
- Timothy Ford, "'Overwatch' Gameplay Architecture and Netcode" (GDC 2017) - https://gdcvault.com/play/1024001 - supports: talk on how Overwatch's networked simulation uses determinism for responsiveness and precision (from the abstract) - checked 2026-11-14
- Jared Cone, "It IS Rocket Science! The Physics of 'Rocket League' Detailed" (GDC 2018) - https://www.gdcvault.com/play/1024972/ - supports: talk on the design and implementation of Rocket League's networked physics (from the abstract) - checked 2026-11-14
- IETF RFC 6455, "The WebSocket Protocol" - https://www.rfc-editor.org/rfc/rfc6455 - supports: "The WebSocket Protocol is an independent TCP-based protocol"; "Message fragments MUST be delivered to the recipient in the order sent by the sender" (previous-tick deltas are safe over WebSocket) - checked 2026-11-14
- IETF RFC 9293, "Transmission Control Protocol (TCP)" - https://www.rfc-editor.org/rfc/rfc9293 - supports: "TCP provides a reliable, in-order, byte-stream service to applications." - checked 2026-11-14
- IETF RFC 768, "User Datagram Protocol" - https://www.rfc-editor.org/rfc/rfc768 - supports: "The protocol is transaction oriented, and delivery and duplicate protection are not guaranteed." (UDP as the unreliable case for acknowledged-baseline deltas) - checked 2026-11-14
- Jean-Sebastien Boulanger, "Interest Management for Massively Multiplayer Games" (MSc thesis, McGill University, 2006; supervisors Kienzle and Verbrugge) - https://www.cs.mcgill.ca/~jboula2/thesis.pdf - supports: "Broadcasting all state changes to every player is not a viable solution"; the Square Tiles algorithm divides the world into equal squares sized to the radius of interest, a subscriber is interested in at most nine tiles (own plus eight neighbours), the cost is constant, and it is a rather bad approximation of the area of interest; smaller tiles filter more messages at higher CPU cost and the gains are not necessarily large - checked 2026-11-14
- Robert Nystrom, "Spatial Partition" (Game Programming Patterns, web edition) - https://gameprogrammingpatterns.com/spatial-partition.html - supports: pairwise tests grow with the square of the unit count; a grid stores each unit in the cell its position falls in; a unit that crosses a cell boundary is removed from its cell list and added to the new one, and nothing changes when it stays inside - checked 2026-11-14
