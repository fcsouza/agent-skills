# Sources

Checked by opening each page on 2026-11-14. Drizzle API names were checked against the published types of drizzle-orm 0.45.4 in the root install.

## Browser storage

- MDN, "Storage quotas and eviction criteria" (developer.mozilla.org, 2026) - https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria - supports: LRU eviction of best-effort origins under pressure, persistent origins skipped; all of an origin's data deleted at once; quotas (Chromium 60% of disk, Firefox 10% of disk or 10 GiB group limit, Safari about 60% for browser apps and 15% for embedded content); localStorage 5 MiB; `QuotaExceededError`; Safari proactive eviction after 7 days without interaction - checked 2026-11-14
- Chrome team, "Persistent storage" (web.dev) - https://web.dev/articles/persistent-storage - supports: "The best time to request your storage be marked as persistent is when you save critical user data, and the request should ideally be wrapped in a user gesture"; Chrome decides by engagement without a prompt, Firefox prompts; persisted storage is not evicted - checked 2026-11-14
- WebKit team, "Full Third-Party Cookie Blocking and More" (webkit.org blog) - https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/ - supports: "deleting all of a website's script-writable storage after seven days of Safari use without user interaction on the site"; home-screen web apps keep their own counter - checked 2026-11-14
- Chrome team, "Storage for the web" (web.dev) - https://web.dev/articles/storage-for-the-web - supports: use IndexedDB for data and OPFS for files; localStorage is synchronous, about 5 MB, strings only, unavailable in workers; "always catch and handle write errors" for `QuotaExceededError` - checked 2026-11-14
- MDN, "Window: localStorage property" - https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage - supports: private-browsing localStorage cleared when the last private tab closes; `SecurityError` on `file:`/`data:` origins and when the user blocks site data or cookies - checked 2026-11-14
- MDN, "Using IndexedDB" - https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB - supports: IndexedDB in private mode lasts in memory only; schema changes only in `onupgradeneeded`; `onblocked` and `onversionchange` with `db.close()` - checked 2026-11-14
- MDN, "Window: showSaveFilePicker() method" - https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker - supports: experimental, not Baseline; secure context and transient user activation required - checked 2026-11-14
- MDN, "IDBTransaction" - https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction - supports: abort rolls back all changes; auto-commit when no requests remain; since Firefox 40 `complete` can fire before data is flushed to disk - checked 2026-11-14
- MDN, "Web Locks API" - https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API - supports: a lock held by one tab or worker blocks the same lock in other scripts of the origin; example of one tab syncing network and IndexedDB; lock released when the callback promise settles - checked 2026-11-14
- MDN, "SubtleCrypto: digest() method" - https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest - supports: SHA-256/384/512, SHA-1 vulnerable, secure contexts only, returns `Promise<ArrayBuffer>` - checked 2026-11-14
- MDN, "Document: visibilitychange event" - https://developer.mozilla.org/en-US/docs/Web/API/Document/visibilitychange_event - supports: "Transitioning to hidden is the last event that's reliably observable by the page" - checked 2026-11-14
- Chrome team, "Page Lifecycle API" (developer.chrome.com) - https://developer.chrome.com/docs/web-platform/page-lifecycle-api - supports: persist state on the hidden transition; `unload` does not fire when mobile users close a tab from the switcher; add `beforeunload` only while there are unsaved changes; check `document.wasDiscarded` - checked 2026-11-14

## Format and versioning

- Wube Software, "Friday Facts #270" (factorio.com) - https://www.factorio.com/blog/post/fff-270 - supports: map version migrations; 0.13/0.14 saves dropped, migrate through 0.16; "saving, exiting, and loading the save shouldn't change any observable behavior" - checked 2026-11-14
- Wube Software, "Friday Facts #444" (factorio.com) - https://factorio.com/blog/post/fff-444 - supports: "Once updated, blueprints and save games cannot be downgraded to 2.0." - checked 2026-11-14
- Philipp Wittershagen, "Deep dive: Creating and fine-tuning the save system of Shadow Gambit" (Game Developer) - https://www.gamedeveloper.com/programming/deep-dive-creating-and-fine-tuning-the-save-system-of-_shadow-gambit_ - supports: a tool warned each programmer when save-load had not been tested for a few minutes; changed compiler-generated class names could break saves across patches - checked 2026-11-14
- Google, "Protocol Buffers: Language Guide (proto3)" (protobuf.dev) - https://protobuf.dev/programming-guides/proto3/ - supports: "Field numbers should never be reused"; absent fields read as defaults; unknown fields preserved - checked 2026-11-14
- Godot Engine, "Saving games" (docs.godotengine.org, stable) - https://docs.godotengine.org/en/stable/tutorials/io/saving_games.html - supports: JSON cannot store Vector2, Color or Quaternion directly and must convert them; binary is smaller - checked 2026-11-14
- Zod, "Basic usage" (zod.dev) - https://zod.dev/basics - supports: `.safeParse()` returns a result object instead of throwing; `.parse()` returns a typed deep clone - checked 2026-11-14

## Writes, servers and integrity

- Microsoft, "Game Saves walkthroughs and samples" (Microsoft GDK docs) - https://learn.microsoft.com/en-us/gaming/gdk/docs/features/common/game-save/game-saves-walkthroughs-and-samples - supports: write to a temporary file "rather than overwriting the live save", close the handle, replace atomically - checked 2026-11-14
- The Open Group, "rename" (POSIX, pubs.opengroup.org) - https://pubs.opengroup.org/onlinepubs/9799919799/functions/rename.html - supports: "a directory entry named new shall remain visible to other threads throughout the renaming operation and refer either to the file referred to by new or old" - checked 2026-11-14
- PostgreSQL Global Development Group, "3.4. Transactions" (PostgreSQL docs) - https://www.postgresql.org/docs/current/tutorial-transactions.html - supports: a transaction is all-or-nothing; committed updates are logged to permanent storage before the commit is reported - checked 2026-11-14
- PostgreSQL Global Development Group, "13.3. Explicit Locking" (PostgreSQL docs) - https://www.postgresql.org/docs/current/explicit-locking.html - supports: "FOR UPDATE causes the rows retrieved by the SELECT statement to be locked as though for update. This prevents them from being locked, modified or deleted by other transactions until the current transaction ends." - checked 2026-11-14
- PostgreSQL Global Development Group, "INSERT" (PostgreSQL docs) - https://www.postgresql.org/docs/current/sql-insert.html - supports: "ON CONFLICT DO NOTHING simply avoids inserting a row as its alternative action"; "Only rows that were successfully inserted or updated will be returned." - checked 2026-11-14
- Drizzle Team, "Transactions" (orm.drizzle.team docs) - https://orm.drizzle.team/docs/transactions - supports: `db.transaction(async (tx) => ...)` runs as one unit and returns the callback's value; the neon-http "No transactions support" error was read in drizzle-orm 0.45.4 `neon-http/session.js` - checked 2026-11-14
- Redis, "Redis persistence" (redis.io docs) - https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/ - supports: RDB alone can lose the latest minutes; AOF with fsync every second can lose one second; use both for safety comparable to PostgreSQL - checked 2026-11-14
- MDN, "If-Match" (HTTP headers) - https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/If-Match - supports: `If-Match` with an ETag prevents lost updates; mismatch returns 412 Precondition Failed - checked 2026-11-14
- Google, "Saved games" (Play Games Services docs) - https://developer.android.com/games/pgs/savedgames - supports: "Usually, the user decides how to resolve these conflicts"; do not automatically overwrite cloud progress when a guest account links; load the latest data on start or resume and save with reasonable frequency; metadata includes last modified and played time - checked 2026-11-14
- OWASP, "MASVS-RESILIENCE" (OWASP MASVS source) - https://raw.githubusercontent.com/OWASP/masvs/master/Document/11-MASVS-RESILIENCE.md - supports: "Anti-tampering or obfuscation techniques must not be used as a substitute for proper security architecture" - checked 2026-11-14
- Gabriel Gambetta, "Client-Server Game Architecture" (gabrielgambetta.com) - https://www.gabrielgambetta.com/client-server-game-architecture.html - supports: "don't trust the player"; the server holds game state, clients send inputs - checked 2026-11-14
- Facepunch Studios, "Devblog 185 - Post Mortem" (rust.facepunch.com) - https://rust.facepunch.com/news/devblog-185---post-mortem - supports: workbench code stopped servers from saving when a player used a workbench during an autosave window of about five seconds; affected servers had to wipe - checked 2026-11-14
- Bun, "File I/O" (bun.com docs) - https://bun.com/docs/runtime/file-io - supports: the page states no atomicity, temp-file rename or fsync guarantee for `Bun.write()`, so the skill does not assume one - checked 2026-11-14

## Platforms

- Valve, "Steam Cloud" (Steamworks docs) - https://partner.steamgames.com/doc/features/cloud - supports: Auto-Cloud syncs at launch and exit with no code; per-user byte and file quotas; separate changing and static files; avoid machine-specific settings; players can disable Steam Cloud globally or per game - checked 2026-11-14
- Microsoft, "XR-052 User State and Title-Save Location, Roaming and Dependencies" (Microsoft GDK docs) - https://learn.microsoft.com/en-us/gaming/gdk/docs/store/policies/XR/XR052 - supports: "Game save data must not have any dependencies on shared content or local storage"; "Titles must not cause unintentional loss of user data"; fail example of cloud saves not recognised on first launch and overwritten on the second device - checked 2026-11-14
