# Sources

Rules marked "this skill's rule" in `SKILL.md` are inferences from these pages to a browser game on a TypeScript server; no page states them. `boilerplate/input-guards.ts` imports nothing, and its limits are placeholders, not numbers from these pages.

## Server authority and input validation

- Gabriel Gambetta, "Fast-Paced Multiplayer (Part I): Client-Server Game Architecture" (gabrielgambetta.com) - https://www.gabrielgambetta.com/client-server-game-architecture.html - supports: "don't trust the player. Always assume the worst – that players will try to cheat."; clients send inputs, the server runs the game and sends results - checked 2026-11-14
- Gabriel Gambetta, "Client-Side Prediction and Server Reconciliation" (gabrielgambetta.com) - https://www.gabrielgambetta.com/client-side-prediction-server-reconciliation.html - supports: "the client adds a sequence number to each request"; the server reply "includes the sequence number of the last input it processed". Dropping repeated numbers to stop replay is this skill's rule - checked 2026-11-14
- Epic Games, "Understanding Networked Movement in the Character Movement Component" (Unreal Engine docs) - https://dev.epicgames.com/documentation/en-us/unreal-engine/understanding-networked-movement-in-the-character-movement-component-for-unreal-engine - supports: the server reproduces the client's move and "checks to see if its position after the ServerMove matches the client's reported end location"; "If the server's timestamp and the client's timestamp have too large of a discrepancy, the client's timestamp is considered expired and the move is discarded"; calculations use the server's timestamps, "preventing clients from hacking their speed by speeding up their local game clock" - checked 2026-11-14
- OWASP, "Input Validation Cheat Sheet" (OWASP Cheat Sheet Series) - https://cheatsheetseries.owasp.org/cheatsheets/Input_Validation_Cheat_Sheet.html - supports: "Client-side validation is bypassable; use it for immediate feedback."; syntax validation versus semantic validation; allowlists over denylists - checked 2026-11-14
- Bun, "WebSockets" (Bun docs) - https://bun.sh/docs/api/websockets - supports: "Bun also closes a WebSocket connection, with code 1009, if it receives a message larger than 16 MB"; `maxPayloadLength` default 16 MB. Setting it near the largest valid message is this skill's rule - checked 2026-11-14

## Hidden information and lag compensation

- Riot Games, "Riot's Approach to Anti-Cheat" (riotgames.com) - https://www.riotgames.com/en/news/riots-approach-anti-cheat - supports: "We don't share the state of other players if it doesn't need to be shared, so we can avoid common cheats like 'map hacks.'"; the server simulation makes authoritative decisions - checked 2026-11-14

- MDN, "Event: isTrusted property" - https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted - supports: `false` when the event was dispatched via `EventTarget.dispatchEvent()`, and for a `click` fired through `HTMLElement.click()` - checked 2026-11-14
